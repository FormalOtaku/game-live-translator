- Context: T-012 parent closeout needs one reproducible command and runbook that ties together first-run stream, backend recovery, and overlay layout evidence without overstating the dependency-free smoke as real Windows/OBS visual validation.
- Options: rely on the three child smoke commands separately; create a docs-only checklist; add a dependency-free closeout smoke that runs the child smokes, validates the closeout runbook/package wiring, and emits privacy-safe aggregate evidence.
- Decision: Add `npm run smoke:first-run-closeout` and `FIRST_RUN_STREAM_CLOSEOUT_RUNBOOK_JA.md`. The closeout command runs the three T-012 child smoke modules through their exported `runSmoke()` contracts, scans their canonical evidence summaries for known raw text/secret/path/stack/cache/debug sentinels, validates runbook/package commands, and prints only child ids, module execution mode, exit-code equivalents, durations, summary byte counts, SHA-256 hashes, child evidence versions, privacy booleans, and `manualGate.reasonCode="WINDOWS_OBS_VISUAL_GATE"`.
- Consequences: T-012 closeout now has a single command suitable for Maestro checkpoints and parent-task validation while preserving privacy-first defaults. The summary cannot leak raw child smoke output, OCR/source text, translated text, provider keys, screenshots, stack traces, raw logs, cache keys, or debug payloads. Real Windows 10/11 + OBS Browser Source confirmation remains an explicit manual gate instead of being implied by the contract smoke.
- Follow-up: At the later Windows/Electron/OBS integration milestone, add real host/browser/OBS validation and record the manual gate result in `PARENT_TASK_CHECKLIST_JA.md`; keep this closeout smoke as the fast CI/devcontainer regression gate.
